Armitage

Armitage is how I use coding agents without giving up learning from first principles. It works natively with Pi, the agent harness it runs on, which has its own terminal interface (TUI) for Armitage; with Zotero, where your PDFs, EPUBs and saved web pages live; and with Zed, through a custom Agent Client Protocol adapter on top of Pi. Every factual claim must point to your workspace, your Zotero library or the agent's memory, or it is cut or marked unverified. Skills and a CLI work with any coding agent, but it is at its best in Zed, through the Pi harness and ACP, where it is most thoroughly tested, or in its own terminal interface.

A personal, experimental tool, built largely with AI coding agents to help me develop Nodens and Nyar. Agent tooling is outside my area of expertise.

Stack: Python Pi Zed ACP ChromaDB Ollama Zotero Obsidian

What makes it different

Six things Armitage does that a plain coding agent does not.

  • 01Verified

    Citations it cannot fake

    Each reference must resolve: the file and line exist, or the Zotero page or section exists in the extracted text. It must also have been looked up in this session, so a source the model only remembers is refused.

  • 02Durable

    Memory that quotes the source

    Findings are stored as the source's own words next to a link to the exact page or passage. The quote is checked against the file, even with Zotero closed and offline.

  • 03Local

    Search that stays on your machine

    Embeddings, keyword search and reranking all run locally. The reranker is loaded for one query and then released, so it fits on a modest GPU.

  • 04Careful

    Studies you approve

    A research plan waits for your approval. The report is refused unless every analysis paragraph cites a page or says Inference, and every quote is found on its page.

  • 05Deliberate

    Designs you approve

    Before a big code change it writes a design file and asks its open questions. The plan cannot be approved with one unanswered, and editing it sends it back to draft.

  • 06Consistent

    Decisions that stick

    When you settle something, Armitage records it with your own words and loads it into every later session, so nothing proposes the opposite.

Built around Zotero, Zed and Pi

Three native integrations: the agent, where your sources live, and where you work. Zed and the terminal both run on Pi.

  • Pi

    The agent harness, with its own terminal interface

    Armitage is built on the Pi harness. In the terminal, armitage pi opens Pi with Armitage's own interface: a header board with your memory vault and Zotero collections; a footer table of what governs the agent (role, access, permission, gate, sandbox) and how it answers, with Zotero and Ollama health and a bar of where the context window goes; and a plan docked above the input bar, with a progress bar, that stays in view while the agent works through it.

    The conversation keeps a hierarchy: your message and the delivered answer are framed, and what the agent did sits quietly beneath. Tool calls fold to one row with a check or a cross, and what the harness attached to your message (a memory sweep, a plan) is a row of its own. ctrl+o expands any of them. The spinner changes with the work, such as searching the Archive, reading, running in the sandbox or auditing citations. Pickers and a /prefs panel change the role and the rest. It all sits in a dark theme of brass, verdigris and umber.

  • Zotero

    Your library is the source

    Armitage reads Zotero 7+ through its local API and never writes to it. Zotero stores your PDFs, EPUBs and saved web page snapshots, and Armitage reads all three, not only PDFs: PDFs page by page, with OCR for scans, EPUBs chapter by chapter, and snapshots section by section.

    Every citation opens at the exact place in Zotero, the page of a PDF or the passage of a snapshot.

  • Zed

    Native in the Agent Panel

    Zed support is a custom Agent Client Protocol (ACP) adapter on top of Pi: Zed talks ACP to the adapter, which drives the same Pi agent, with Armitage's extensions, roles and gate, that the TUI uses. Its questions and approvals appear as native cards, and a code citation opens the file in Zed at the cited line.

The skills and CLI are the portable base; the best way to use Armitage is inside Zed, through Pi and ACP, or in its terminal interface on Pi. Each way, as it looks.

How a question is answered

                    
One search across your memory, code and papers, then four steps to an answer with a source
                        for every claim.

                

                

                    
    
                        
  1. 1
                            
    
                                
    Ask: One question
    
                                
    A single query fans out across its memory, your papers and your code at once
                                    (armitage search).
    
                            
    
                        
    2. 
                        
  2. 
                            
      
                                
    • 
                                    Memory
                                    
      The agent's own notes, kept as Markdown in an Obsidian vault: plans, decisions,
                                        concepts and your profile.
      
                                
      • 
                                
    • 
                                    Papers, books & web
                                    
      Your local Zotero 7+ library, read-only. Reads every file Zotero's reader opens:
                                        PDFs (with OCR for scans), EPUBs by chapter, and saved web snapshots.
      
                                
      • 
                                
    • 
                                    Code
                                    
      An index of your repositories, shared across branches and worktrees. Looking up a
                                        symbol or where it is used needs no AI model.
      
                                
      • 
                            
    
                        
    3. 
                        
  3. 2
                            
    
                                
    Match: Meaning + keywords
    
                                
    In each of those three sources, embedding search (Ollama) finds passages by meaning
                                    and SQLite full-text search finds exact words.
    
                            
    
                        
    4. 
                        
  4. 3
                            
    
                                
    Rank: Best passages first
    
                                
    Matches from all three sources are merged, then a reranking model (Qwen3) puts the
                                    most relevant passages first.
    
                            
    
                        
    5. 
                        
  5. 4
                            
    
                                
    Cite: Every claim sourced
    
                                
    Each factual statement carries an inline [^n] footnote to its source.

How a claim earns its source

                    
What happens between your question and a cited answer.

                

                

                    
    
                        
  1. 1
                            
    
                                
    Sweep
    
                                
    On your first fact-bearing question, it recalls memory, plans, code or literature
                                    within about three seconds and puts the evidence in front of the model.
    
                                
    Earlier work is reused, not rediscovered.
    
                            
    
                        
    2. 
                        
  2. 2
                            
    
                                
    Look up
    
                                
    The agent reads the code or queries Zotero for the passages it needs.
    
                                
    Claims rest on sources, not on what the model remembers.
    
                            
    
                        
    3. 
                        
  3. 3
                            
    
                                
    Answer
    
                                
    Factual answers go through an answer form with the claims and their references, not
                                    free prose.
    
                                
    Every claim has a place for its source.
    
                            
    
                        
    4. 
                        
  4. 4
                            
    
                                
    Audit
    
                                
    Each footnote is checked: the file and line exist and were read, the Zotero item was
                                    returned this session and the page exists.
    
                                
    Invented or half-remembered sources are rejected.
    
                            
    
                        
    5. 
                        
  5. 5
                            
    
                                
    Correct
    
                                
    If a check fails, the agent is sent back, up to three times. If it still fails, you
                                    see a visible warning and the answer is flagged.
    
                                
    Nothing passes silently.
    
                            
    
                        
    6. 
                    

                

            


            

                

                    
Retrieval, step by step

                    
One pipeline serves memory, code and papers.

                

                

                    
    
                        
  1. 1
                            
    
                                
    Extract
    
                                
    Everything Zotero stores is read: PDFs page by page (scans through OCR), EPUBs by
                                    chapter, and web snapshots by section.
    
                                
    Every chunk keeps its page, so a citation can name it.
    
                            
    
                        
    2. 
                        
  2. 2
                            
    
                                
    Index
    
                                
    Text is chunked, embedded with a local Ollama model into Chroma, and indexed for
                                    keywords with SQLite FTS5.
    
                                
    Meaning and exact words both match.
    
                            
    
                        
    3. 
                        
  3. 3
                            
    
                                
    Fuse
    
                                
    The top 50 matches by meaning and the top 50 by keywords merge into 20 candidates by
                                    reciprocal rank fusion.
    
                                
    Ranks are comparable where raw scores are not.
    
                            
    
                        
    4. 
                        
  4. 4
                            
    
                                
    Rerank
    
                                
    A Qwen3 reranker keeps the best 5. One pass orders memory, code and papers together.
                                
    
                                
    A note, a function and a paper compete on merit.
    
                            
    
                        
    5. 
                        
  5. 5
                            
    
                                
    Cite
    
                                
    Each hit carries its citation: a Zotero page, a snapshot link, a note link or a
                                    path:line.
    
                                
    The index produces the citation, not the model.
    
                            
    
                        
    6. 
                    

                

            


            

                

                    
What it remembers

                    
Plain Markdown in a vault on your disk. Obsidian is optional, and the CLI notices edits made
                        behind its back.

    Pointer records
    
                                
    The source's exact words, linked to the page. Quick recall without paraphrasing the
                                    source.
    
                            
    
                        
    • 
                        
  • Research
                            
    
                                
    Plans and reports
    
                                
    Approved plans and cited reports. Later sessions find what a study established.
    
                            
    
                        
    • 
                        
  • Design plans
                            
    
                                
    Why it was built that way
    
                                
    The goal, decisions, architecture and open questions of a big change.
    
                            
    
                        
    • 
                    

                    
    
                        
  • Decisions
                            
    
                                
    What you settled

  • Profile
                            
    
                                
    Who you are to it
    
                                
    Preferences, corrections, goals and dated events. It adapts to you, and the shell
                                    cannot rewrite it.

Roles

                    
Roles build on skills. Each role loads the skills it is charged with and adds a workflow of its
                        own, consolidated from the literature: books and papers cited by page in the role's
                        instructions. A role also sets what Armitage may touch. You pick one with /role,
                        and only you can switch it.

Staying in control

                    
The agent has a shell and your notes, so it is contained in layers. The sandbox is not a claim of
                        perfect isolation, and the project documents its known limits.

                

                

                    
Contains the agent

                    
    
                        
  • Shell
                            
    
                                
    Sandboxed commands
    
                                
    Runs in bubblewrap with an empty root and no network, with SSH, AWS and GPG folders
                                    hidden. Without the sandbox, the shell refuses to run.
    
                            
    
                        
    • 
                        
  • Files
                            
    
                                
    File-tool guard
    
                                
    Writes outside the workspace are refused, and reads outside it ask you first.
    
                            
    
                        
    • 
                        
  • Rules
                            
    
                                
    Protected rules
    
                                
    Its skills, persona and your profile are read-only to the agent, so it cannot widen
                                    its own sandbox.
    
                            
    
                        
    • 
                        
  • Models
                            
    
                                
    Local only
    
                                
    The CLI refuses a non-local Ollama host unless you opt in.
    
                            
    
                        
    • 
                    

                    
Keeps you in charge

                    
    
                        
  • Commands
                            
    
                                
    Permission prompts
    
                                
    Commands ask before running: all of them, only risky ones, or none. Allow and deny
                                    rules can be set per command. In the TUI the footer always shows the current role, access,
                                    permission and gate level.
    
                            
    
                        
    • 
                        
  • Roles
                            
    
                                
    Read-only roles
    
                                
    The researcher, tutor, planner and debug roles cannot change your files. Their builds
                                    and tests run in a throwaway overlay.
    
                            
    
                        
    • 
                        
  • Library
                            
    
                                
    Zotero untouched
    
                                
    Armitage never writes to your Zotero library. The one opt-in OCR option rewrites a
                                    PDF file and keeps the original.
