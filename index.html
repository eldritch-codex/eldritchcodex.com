IFRAMEWORK experimental

Nodens

An experimental C++23 framework for building interactive desktop applications quickly, with an optional immediate-mode GUI (Dear ImGui). Everything is exposed as C++ modules, so an app starts with import nodens;, and the framework links as a single static library.

  • C++23
  • Linux
  • Static library
Links
  • Repository
  • Wiki
  • App template
01 · Windowing

GLFW windows

Creates the window, graphics context and input handling, with OpenGL or Vulkan backends.

02 · Lifetime

Layer system

An app is a stack of layers. They update in order, draw back to front, and receive input from the top down.

03 · Messaging

Event system

Input events pass down the layers. A thread-safe event bus lets any part of the app publish and subscribe to custom events, handled immediately or queued.

04 · Concurrency

Job system

Runs heavy work, like simulation and data processing, on worker threads so the render thread stays responsive.

Writing an app

  • An app inherits from Nodens::Application, pushes one or more layers, and calls Run(). Every frame, each layer receives OnEvent, OnUpdate(TimeStep) and OnImGuiRender(TimeStep).
  • Two examples ship with it: circularwave3d (live 2D/3D plots with ImPlot and ImPlot3D) and planetaryscan (the event bus and job system working together).
  • Tracy profiling is built in: add ZoneScoped inside any layer method to see it in the profiler.
  • CMake downloads and builds every dependency from source, so there is nothing to install by hand.

IIRENDERER experimental

Nyar

A Vulkan 1.3 real-time renderer built as a separate module for Nodens, and a learning exercise in modern graphics APIs. It starts from the official Khronos "Drawing a triangle" tutorial and is refactored step by step into a clean rendering API.

  • Vulkan 1.3
  • Slang
  • C++23
Links
  • Repository
  • Milestones
01 · Shaders

Slang to SPIR-V

Shaders are written in Slang, a shading language, and compiled to SPIR-V (the format Vulkan loads) by a custom CMake target.

02 · Pipeline

Modern Vulkan 1.3

Uses Vulkan's current features: dynamic rendering (no render pass objects), synchronization2 and extended dynamic state.

03 · Direction

Nodens integration

Packaged as a C++ module (export module nyar;) that Nodens applications import as their rendering backend.

IIIAGENT, SKILLSET & CLI private preview

Armitage

Armitage brings source-grounded research and engineering to coding agents through skills, a command-line tool, a custom Pi harness and a Zed integration via ACP. The Pi harness and Zed ACP integration are optional, but central parts of the project: the dedicated agent environment, in the terminal or inside the editor. The skills and CLI also work with other coding agents. Every factual claim must point to your workspace, your Zotero library or the agent's memory, or it is cut or marked unverified.

  • Python 3.14
  • Pi harness
  • Zed ACP
  • Zotero
  • Obsidian
Links
  • Private repository · public release upcoming
About Armitage

I love understanding things from first principles, grounded in true sources: books, documentation and papers. Armitage is how I take advantage of agentic workflows while keeping that habit: a tool tailored to my own use case, built to help me learn and develop Nodens and Nyar with every claim traceable to its source. It is built largely with AI coding agents, and agent tooling is outside my area of expertise (my background is graphics and numerical simulation), so treat it as a personal, experimental tool.

Ways to use it

Start with the skills and CLI; the other two are optional.

Core

Skills & CLI

The portable foundation: instructions for your coding agent, plus a CLI that maintains memory and searches your code and Zotero library. No Pi harness or Zed integration required.

Optional

Custom Pi environment

A dedicated agent environment built around Armitage's source-grounded workflow. Run it in the terminal with armitage pi; this is where Armitage works best.

Optional · needs Pi

Zed via ACP

Run the Pi harness inside Zed's Agent Panel through the Agent Client Protocol, instead of a separate terminal.

How a question is answered

One search, four steps.

01 · Ask

One question

A single query searches its memory, your code and your papers together (armitage search).

02 · Match

Meaning + keywords

Embedding search (Ollama) finds passages by meaning; SQLite full-text search finds exact words.

03 · Rank

Best passages first

Both result lists are merged, then a reranking model (Qwen3) puts the most relevant first.

04 · Cite

Every claim sourced

Each factual statement carries an inline [^n] footnote to its source.

Where it looks

  • Memory (armitage memory): the agent's own notes, written and maintained by the agent as plain Markdown in an Obsidian vault: plans, decisions, concepts and your profile.
  • Papers and books (armitage zotero): your local Zotero 7+ library, read-only, with PDF text extraction and OCR for scanned pages.
  • Code (armitage code): an index of your repositories, shared across branches and worktrees. Looking up a symbol or where it is used needs no AI model.
