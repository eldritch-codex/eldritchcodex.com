Nodens

Repository ↗ Wiki ↗ App template ↗

An experimental C++23 framework for rapidly building interactive desktop applications with an optional immediate-mode GUI. Public APIs are C++ module interfaces (.cppm), third-party headers stay isolated inside the global module fragment, and the whole framework links as a single static library.

01 · Windowing

GLFW windows

Window, context, and input management with both OpenGL and Vulkan backends.

02 · Lifetime

Layer system

Governs execution order, visual rendering priority, and top-to-bottom input routing.

03 · Messaging

Event system

Input events route down the LayerStack; a thread-safe pub/sub EventBus dispatches custom events immediately or queued.

04 · Concurrency

Job system

Multithreaded task execution so simulation and data work stay off the render thread.

Consumer code starts with import nodens;

Applications inherit from Nodens::Application, push one or more layers, and call Run(). Each layer receives OnEvent, OnUpdate(TimeStep), and OnImGuiRender(TimeStep) every frame.

  • Ships with two examples: circularwave3d (live 2D/3D plotting with ImPlot and ImPlot3D) and planetaryscan (event bus + multithreaded job system).
  • Built-in Tracy frame and GPU profiling — drop ZoneScoped into a layer method to trace it.
  • All dependencies are fetched and compiled from source at configure time via CMake FetchContent.

Nyar

Repository ↗ Milestones ↗

A Vulkan real-time renderer built to serve as a dedicated module for Nodens. It is being grown from first principles — starting with the Khronos Vulkan tutorial baseline and refactoring step by step into a clean rendering API.

01 · Shaders

Slang to SPIR-V

Shaders are authored in Slang and compiled directly to SPIR-V 1.4 by a custom CMake target invoking slangc.

02 · Pipeline

Modern Vulkan 1.3

Uses import vulkan; along with dynamicRendering, synchronization2, and extended dynamic state.

03 · Direction

Nodens integration

Packaged as export module nyar; so Nodens applications can import it as their rendering backend.

Armitage

Repository ↗ Engineering docs ↗ Changelog ↗

A skillset and a CLI for source-disciplined development, work, and research. The armitage-* skillset enforces a citation gate on the model; the armitage CLI runs the memory cache, the code index, and the Zotero RAG pipeline. Any claim that cannot be traced to the workspace, the Archive (Zotero), or the Ledger (Obsidian) is cut or marked unverified.

01 · Intake

armitage search

One query spans memory, code, and Zotero together.

02 · Hybrid recall

Dense + FTS5

Ollama qwen3-embedding-rag vectors paired with SQLite FTS5 keyword search.

03 · Fusion & rerank

RRF → Qwen3

Reciprocal rank fusion scored by a Qwen3 cross-encoder reranker.

04 · The gate

Cited claim

Every factual statement carries an inline [^n] footnote to its source.

Three corpora, one discipline

  • The Ledger (armitage memory) — plain-Markdown vault in Obsidian holding plans, standing decisions, concept notes, and user profile.
  • The Archive (armitage zotero) — local Zotero 7+ library with PDF extraction via pdf-inspector, layout-aware OCR with PaddleOCR-VL, and resumable indexing.
  • Code index (armitage code) — content-addressed tree-sitter index shared across branches and worktrees; symbol and refs need no model.
  • Pi persona (armitage pi) — bundles extensions, roles, and an ACP adapter for Zed.
