IFRAMEWORK experimental

Nodens

A C++23 framework for building interactive desktop applications quickly, with optional Dear ImGui. Everything is a C++ module, so an app starts with import nodens; and links one static library.

Stack: C++ OpenGL Vulkan GLFW GLAD ImGui ImPlot ImPlot3D spdlog Tracy
Links
  • Full overview
  • Repository
  • Wiki
  • 01 · Windowing

    GLFW windows

    Creates the window, graphics context and input handling, with OpenGL or Vulkan backends.

  • 02 · Lifetime

    Layer system

    An app is a stack of layers. They update in order, draw back to front, and receive input from the top down.

  • 03 · Messaging

    Event system

    Input events pass down the layers. A thread-safe event bus lets any part publish and subscribe to custom events, handled immediately or queued.

  • 04 · Concurrency

    Job system

    Runs heavy work, like simulation and data processing, on worker threads so the render thread stays responsive.

Writing an app

  • An app inherits from Nodens::Application, pushes one or more layers, and calls Run(). Every frame, each layer receives OnEvent, OnUpdate(TimeStep) and OnImGuiRender(TimeStep).
  • Two examples ship with it: circularwave3d (live 2D/3D plots with ImPlot and ImPlot3D) and planetaryscan (the event bus and job system working together).
  • Tracy profiling is built in: add ZoneScoped to any layer method.
  • CMake builds every dependency from source, so there is nothing to install by hand.

IIRENDERER experimental

Nyar

A real-time Vulkan 1.3 renderer, built as a separate module for Nodens as a learning exercise. It starts from the Khronos "Drawing a triangle" tutorial and is refactored step by step into a clean rendering API.

Stack: C++ Vulkan Vulkan-Hpp Slang GLFW SPIR-V Nodens
Links
  • Full overview
  • Repository
  • Milestones
  • 01 · Shaders

    Slang to SPIR-V

    Shaders are written in Slang, a shading language, and compiled to SPIR-V (the format Vulkan loads) by a custom CMake target.

  • 02 · Pipeline

    Modern Vulkan 1.3

    Uses Vulkan's current features: dynamic rendering (no render pass objects), synchronization2 and extended dynamic state.

  • 03 · Direction

    Nodens integration

    Packaged as a C++ module (export module nyar;) that Nodens applications import as their rendering backend.

Armitage

Armitage is how I use coding agents without giving up learning from first principles. It works natively with Zotero, where your PDFs, EPUBs and saved web pages live, and with Zed, through the Agent Client Protocol. EventBus and producer threads Armitage · illustrative
You

How does the Nodens EventBus keep producer threads from blocking while events are being dispatched?

Armitage
  • armitage code symbol QueueEvent1 definition
  • armitage code symbol EventBus::Flush1 definition
  • armitage search "EventBus thread safety"3 passages

Producers never wait for handlers. QueueEvent takes a short mutex, appends the event's bytes to the active write buffer and returns.1 Flush() holds that mutex only to swap the two buffers, then runs the handlers on the retired buffer outside the lock.2 Subscribe, Unsubscribe and QueueEvent may be called from any thread; Dispatch and Flush are meant for the main thread.3

Unsourced. How the single buffer mutex behaves under heavy contention: none of the code, docs or papers searched measure it.

  1. Nodens/Events/EventBus.cppm:108-112 · QueueEvent locks the buffer mutex, appends the bytes to the active buffer and returns
  2. Nodens/Events/EventBus.cpp:66-69, 95 · Flush swaps the buffer index under the lock; handlers run after it is released
  3. Nodens/Events/EventBus.cppm:37-39 · thread-safety note on the class

Vulkan synchronization Armitage · illustrative
You

How can a Vulkan renderer like Nyar cut down on synchronization bookkeeping?

Armitage
  • armitage zotero query "image layout transitions and pipeline barriers with synchronization2" -c vulkan5 passages · 2 sources
  • armitage zotero cite 4YKVG2VK -q "Synchronization2"verified · p. 100

The SIGGRAPH 2026 Vulkan slides name three tools. Timeline semaphores let one semaphore stand for many increasing milestone values that the CPU and GPU can wait on, although swapchain acquire and present still use binary semaphores. Synchronization2, core since Vulkan 1.3, gives clearer dependency and submission structures. Unified image layouts mean fewer layout transitions.1 The Khronos Vulkan Tutorial shows the step they simplify: a pipeline barrier that commits an image layout transition to the command buffer together with its source and destination stages.2

Unsourced. How much these changes save: the slides present them as less bookkeeping, not as measured speedups.

  1. How to Write a Vulkan Application in 2026 · p. 100 · Potter et al. 2026, SIGGRAPH 2026 (Vulkan Documentation Project, free online)
  2. Image Layout Transition · §46.1.14 · Khronos Vulkan Tutorial, Barrier Execution and GPU Synchronization (free online)

Why the reranker is released Armitage · illustrative
You

Why does Armitage release the reranker after every query?

Armitage
  • armitage memory recall "reranker"2 notes · both stale
  • armitage code symbol Reranker.close1 definition
  • armitage search "reranker keep_alive"3 passages

Memory has the answer but marks it stale, so I rechecked it against the docs and code, and it still holds. The reranker is loaded for one query and then released, and the query path unloads the embedding model first, so the two models never sit in VRAM together.1 In code, Reranker is a context manager whose __exit__ calls close(),2 which moves the model off the GPU, empties the CUDA cache and logs the release.3 The query embedding uses keep_alive=0, which is what unloads that model.4

Unsourced. How much VRAM the loaded reranker takes in total: the docs bound it but give no measured figure.

  1. docs/03-retrieval-pipeline.md:207-210 · bounded VRAM: reranker loaded for one query then released, embedding model unloaded
  2. armitage_cli/retriever.py:191-196 · context manager; __exit__ calls close()
  3. armitage_cli/retriever.py:290-305 · close() frees the model and the CUDA cache, then logs the release
  4. armitage_cli/retriever.py:380, 453 · embedding call defaults to keep_alive=0
